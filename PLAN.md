### 1.1 Профиль реальной коллекции (замер по всем 677 файлам)

Полный отчёт — `research/collection-profile.md` + `.json`, скрипт — `research/fb2_profile.py`,
таблица жанров — `research/genre-codes.txt`.

- **Битых нет:** 677/677 — валидный zip, ровно один `.fb2`-entry, XML парсится. 0 ошибок.
- **Метаданные в XML почти всегда полные:** `<book-title>` и `<author>` — 100%; авторов 1 → 624,
  2 → 53; `<annotation>` — 97.0%; `<coverpage>` — 94.4%, и **у всех** `l:href` разрешается в
  существующий `<binary>`.
- **Серии:** 84.8% (1 серия → 565, 2 → 9); с `number` — 510; номера **только целые** (0…1184),
  форм «1-2» нет; 72 `<sequence>`-узла без номера.
- **Жанры:** 99.9%; **74 разных сырых кода**, после нормализации — 69. Алиасы:
  `sf-history`≡`sf_history`, `back-to-ussr`≡`back_to_ussr`, `popadancy`≡`popadanec`≡`popadantsy`.
  Топ: `network_literature` (304), `popadancy` (203), `sf_history` (176).
- **Кодировки:** UTF-8 653 (96.5%), **windows-1251 23 (3.4%)**, **utf-16 1**. Без декларации — 0.
- **Ловушка UTF-16:** у wide-кодировки байтовый regex XML-декларацию «не видит» — нужен
  BOM/`0x00`-детект до чтения декларации.
- **Entry-имена:** 54 из 677 — в **cp866** (флаг UTF-8 не выставлен); внутреннее имя **отличается**
  от имени zip у **455** (396 информативны: транслит-автор + id). Уникальных entry-имён 617 →
  **53 группы дублей (113 файлов)** по entry-имени.
- **Имя файла как источник:** лишь 55.1% дают автора через `_`, 13.7% — «Автор. Название»,
  **31.2% — только название** (автор из имени не выводится).

Выводы: источник истины — XML, имя файла — только fallback; матчить `.fb2` **по расширению**;
поддержать windows-1251 и UTF-16; жанры нормализовать и маппить; обложки — лениво (безопасно).

## 2. Границы и роль

Как в `SPEC.md` §1, с уточнениями:

- Приложение = **каталог + пускач**. Само **не** читает и **не** рендерит** книги.
- **Не** заменяет домашний экран (решение §0).
- Форматы: FB2, EPUB, MOBI. Индексация — **только метаданные**, содержимое не
  читается и не индексируется (поиск — по названию/авторам/серии; см. §12.6).
  PDF/DJVU **не поддерживаются** (сняты решением оператора; см. §0).

## 3. Технологический стек (зафиксировано: Java без Gradle)

Опирается на уже работающий в дереве шаблон (`toolbox/build.sh`, `floating-nav/build.sh`).

- Сборка: `aapt2 → javac --release 8 → d8 → zipalign → apksigner`. Никакого Gradle, никаких
  AAR/JAR из сети. Скрипт — `build.sh` проекта.
- Язык: **Java 8** (desugaring делает `d8`; `--min-api` = minSdk).
- БД: **`android.database.sqlite`** напрямую + **FTS4** (§6). Свой DAO-слой.
- Списки: **`ListView` + `CursorAdapter`** (виртуализация из коробки, без AndroidX).
- Вёрстка: масштаб шрифта через override `Configuration.fontScale`; высота строк — `wrap_content`.
- Фоновая работа: `Service` + `HandlerThread`/`ExecutorService`; свой `ProgressBus`.
- Кэш: `LruCache` (memory) + свой дисковый LRU; `RGB_565` для миниатюр.
- DI: ручной (синглтоны в `App`). Логи: свой `Logger` (файл + `logcat`).
- Целевые параметры: `minSdk` 23 (вопрос §12.9), `targetSdk` 30; ABI `arm64-v8a` (нативных
  частей не планируется); package `ru.unclerus.library`.

Ожидаемый эффект: APK ~0.3–0.6 МБ (мультиформат добавляет только свой код), быстрый холодный
старт, минимальный расход ОЗУ, сборка полностью офлайн.

## 5. Модель данных

```sql
PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL; PRAGMA foreign_keys=ON;

root(id PK, uri, path, kind /*file|saf*/, enabled, last_scan_at,
     volume_state, permission_state, last_error);

scan_state(key PK, value);
dir_cache(root_id, path, mtime, scanned_at, PRIMARY KEY(root_id, path));

book(
  id PK,
  root_id REFERENCES root(id),
  path, file_size, file_mtime,
  format TEXT,            -- fb2|epub|mobi  (детект по расширению+magic)
  title, title_norm, title_letter,   -- title_letter: буква раздела для группировки/указателя
  authors_text, series_text,         -- денормализованные строки для показа и FTS
  authors_norm, series_norm,         -- регистронезависимые копии для LIKE-fallback
  annotation,
  meta_ok INTEGER DEFAULT 0, needs_parse INTEGER DEFAULT 1, seen_gen INTEGER DEFAULT 0,
  cover_entry TEXT,       -- «где лежит» картинка внутри файла (entry-имя/индекс), формат-специфично
  cover_state TEXT DEFAULT 'none' /*none|pending|cached|absent*/, cover_cache_path,
  entry_id TEXT,          -- внутр. имя entry / fictionbook-id: вторичный ключ, отметка дублей
  indexed_at,
  availability TEXT DEFAULT 'ok' /*ok|missing|no_access*/,
  last_opened_at DEFAULT 0, open_count DEFAULT 0, last_opened_by_package,
  UNIQUE(root_id, path)
);

author(id PK, name, name_norm, sort_name, surname, letter, UNIQUE(name_norm));
-- letter: буква раздела (фамилии) для группировки и алфавитного указателя
book_author(book_id, author_id, ord, PRIMARY KEY(book_id, author_id));
genre(id PK, code UNIQUE, display_name, display_name_en);  -- RU/EN: имя по локали
book_genre(book_id, genre_id, PRIMARY KEY(book_id, genre_id));
series(id PK, name, name_norm, UNIQUE(name_norm));
book_series(book_id, series_id, number TEXT, number_sort INTEGER, PRIMARY KEY(book_id, series_id));

author_book_count(author_id PK, cnt);
genre_book_count(genre_id PK, cnt);
series_book_count(series_id PK, cnt);

CREATE VIRTUAL TABLE book_fts USING fts4(title, authors_text, series_text,
  tokenize=unicode61);           -- НЕ external content (см. §6.1)
-- Триггеры book_ai/book_ad/book_au синхронизируют индекс обычными INSERT/DELETE по rowid.
```

Индексы: `book(root_id, availability)`, `book(file_mtime)`, `book(last_opened_at DESC)`,
`book(title_letter, title_norm)`, `book(needs_parse)`, `book(format)`, `author(letter, sort_name)`,
FK-таблицы (`book_genre(genre_id)`, `book_series(series_id)`), `dir_cache(root_id)`.

Миграции — `Db.onUpgrade` шаг за шагом, `Schema.VERSION = 4`: v2 — `book_fts` не external content;
v3 — удаление снятых форматов (PDF/DJVU); v4 — `genre.display_name_en` (английское название жанра,
заполняется из кода `GenreTable`, без перечитывания файлов).

## 6. Ключевые технические решения

### 6.1 [Поправка к SPEC §4 FR-4] Поиск: FTS4 вместо FTS5
Факт: в `libsqlite.so` устройства есть `fts3`/`fts4`/`unicode61`, **fts5 нет**.
Значит: FTS4 + `tokenize=unicode61` (корректно для кириллицы) + триггеры синхронизации.

**Индекс — НЕ external content** (исправлено в M3a). External-content FTS4 не даёт корректно
удалять/обновлять строки: `DELETE FROM book_fts WHERE rowid=?` читает контент-таблицу и старые
токены не снимаются, а спецкоманда `INSERT INTO book_fts(book_fts,…) VALUES('delete',…)` —
это синтаксис **FTS5** (в FTS4 → «SQL logic error»). Поэтому `book_fts` — обычная FTS4-таблица,
текст дублируется в индексе (для 100k приемлемо), а триггеры делают обычные `INSERT`/`DELETE`
по `rowid`. Проверено: обновление автора снимает старые токены, вставка/удаление согласованы.

**Префикс** — только «голым» токеном: `MATCH 'префикс*'`. Форма `"слово"*` (звёздочка после фразы)
префиксом **не** является и даёт 0 совпадений — учтено в `SearchDao.toMatch` (последнее слово —
`слово*`, предыдущие — точные фразы).

Поиск **внутри** слова FTS не умеет → для коротких запросов (длиной < 3) fallback на `LIKE`
по `*_norm` (на 677 книгах мгновенно, на 100k — медленно; см. §12.6).
Тест FTS4+unicode61 — обязателен на M0.

### 6.2 [Поправка к SPEC §3.2] Доступ к файлам
Основной путь — `MANAGE_EXTERNAL_STORAGE` + прямой `java.io.File` по `/storage/6D4A-1E15` и
`/sdcard`. SAF (`DocumentFile`) — только fallback для разделов без прямого доступа.
Получение разрешения: экран `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` (пакет
`com.android.settings` на устройстве есть и запускается), либо `adb shell appops set ...allow`.

### 6.3 Мультиформат: единый интерфейс `MetadataReader`
- Детект формата по расширению с проверкой magic (ZIP → посмотреть `mimetype`/`container.xml`:
  EPUB vs FB2-ZIP; PDB-заголовок MOBI).
- Каждый ридер отдаёт `BookMeta` (title, авторы[], серии[]+номер, жанры[], аннотация, `coverSpec`).
- FB2: `*.fb2.zip` (entry `.fb2`) и `*.fb2`. По замеру коллекции обязательно:
  **матчинг entry по расширению** (56 из 699 доступных zip — имена cp866 без флага UTF-8:
  Android-11 бросает `IllegalArgumentException: MALFORMED[1]`, лечится переоткрытием `ZipFile`
  с `Cp866`), кодировки **utf-8 / windows-1251 /
  utf-16** с BOM/`0x00`-детектом *до* чтения XML-декларации, жанры — нормализация кода
  (lower, `-`→`_`) + таблица «код → RU/EN» с алиасами, номер серии — целое (сортировка числовая).
  Имя entry (fictionbook-id) хранить как вторичный идентификатор для отметки дублей.
- EPUB (реализовано, M3b): `META-INF/container.xml` → OPF. Из OPF: `dc:title`,
  `dc:creator` (фамилия эвристикой `Text.surname`, ключ сортировки «Фамилия Имя»), `dc:description`
  (HTML → плоский текст), `dc:subject` (только сводимые к известному коду `GenreTable`), серия —
  `calibre:series`+`calibre:series_index` либо EPUB3 `belongs-to-collection`+`group-position`,
  обложка — `meta name="cover"` → manifest-id либо `item properties="cover-image"` (путь внутри
  архива, относительно каталога OPF). Если `container.xml` битый/указывает в никуда — ищется
  первый `*.opf` в архиве.
- MOBI (реализовано, M3c): контейнер PDB; читается только запись 0 (PalmDOC + MOBI-заголовок
  + EXTH). Полное имя — MOBI `+0x44/+0x48` (перекрывается EXTH 503), авторы — EXTH 100,
  описание — 103, `subject` — 105 (только сводимые к коду `GenreTable`). Обложка — EXTH 201
  (offset от первой image-записи по MOBI `+0x5C`) либо 202, иначе первая image-запись;
  в `cover_entry` — **номер записи PDB** (разрешит `CoverStore` в M6, формат `mobi`).
  Кодировка — MOBI `+0x0C` (65001 → UTF-8, иначе windows-1252). Тело книги и картинки не читаются.
- Формат снят с поддержки: **PDF/DJVU** (решение оператора). Читателей нет; Фаза A не распознаёт
  эти файлы как книги, миграция схемы v3 вычищает их строки из каталога.
- Итог по обложкам: есть у FB2 / EPUB / MOBI; у прочих (неподдерживаемых) форматов — нет.
- **Названия жанров локализованы**: `GenreTable` даёт по коду **русское и английское** названия; в БД
  хранятся обе колонки (`genre.display_name` / `display_name_en`), а имя для показа **и сортировки**
  выбирается по языку приложения (`util.Lang` — совпадает с выбором `values-en`). И список жанров
  (`GenreDao`), и ссылки-жанры в карточке (`BookDao.genresOf`) берут одну и ту же колонку, поэтому
  порядок всегда совпадает с показом. Данные книг/авторов/серий не переводятся.

### 6.4 Масштаб 100k+
- Оконные курсоры (`LIMIT/OFFSET` или keyset-пагинация) — в памяти только видимое окно.
- Материализованные счётчики классификаторов (не `GROUP BY` «в лоб» на каждый показ).
- `dir_cache` — повторный скан неизменённых поддеревьев без обхода (только `stat`, приёмочный №9).
- Фазы идемпотентны и возобновляемы без явного курсора (чекпойнт = состояние в БД).
- Лимиты кэшей, `RGB_565`, аккуратные `Bitmap`-бюджеты.

### 6.5 Счётчики и целостность: «никаких групп без книг»
- Списки и счётчики вкладок формируются **только по группам с `cnt > 0`** (`author_book_count.cnt > 0`
  и т.п.) — автор/жанр/серия без книг не появляется.
- Книга со статусом `missing` **остаётся** в каталоге и в группах (её метаданные сохранены) —
  «подвисшей» считается только связь без единой книги.
- «Очистить отсутствующие» (`D4`, `S4.9`) удаляет записи книг **и** связи-сироты, а также
  пересчитывает счётчики — в одной транзакции.
- Периодическая проверка целостности (при старте/по кнопке в S6) чистит сироты на случай
  рассинхрона (прерванная индексация, ручное вмешательство).

### 6.6 Группировка по буквам и пагинация (масштаб 100k+)

- **Авторы** сортируются по **фамилии** (`author.sort_name`), список бьётся на **буквы-заголовки**
  (`V13`). **«Все книги»** при сортировке по названию — буквы по `book.title_norm`.
- Фамилия берётся безошибочно из FB2 (`<last-name>`); для EPUB/MOBI — эвристика
  `author_surname()`: до запятой («Фамилия, Имя») / последнее слово («Имя Отчество Фамилия») /
  слово перед инициалами («Фамилия И. О.») / одно слово (ник). Буква — `first_letter()`: пропускает
  кавычки и знаки («Краткая…» → К), не-буквенное начало → «#». Нормализация «ё»→«е», нижний регистр.
- Заголовки букв — **обычные строки списка** (не sticky), как и заголовки дат (e-ink, ghosting).
- Фон заголовков — серый **`#808080`** (белый жирный текст), вертикальные отбивки **4 dp**. Незанятое
  место списка под последней строкой затянуто **дизерингом** (тайл 10×10 px, точка 2×2 px `#404040`),
  а не сплошной серой заливкой; строки-ряды непрозрачно белые, пустые состояния — чистый белый
  (палитра — `UI.md §6.3`).
- **Группировка книг автора по сериям** (`S2`): книги автора бьются на группы по названию серии,
  **«Без серии»** — в конце; внутри — по номеру в серии, затем по названию. У автора и серии порядок
  **фиксирован**, строка сортировки скрыта; у жанра и группы даты строка сортировки сохраняется (`D8`).
  Заголовок разрезанной серии повторяется на новой странице (как и у букв/дат).
- **Режим сортировки помнится между запусками — отдельно по контексту**: «Все книги»
  (`Prefs.K_SORT_BOOKS`), книги **жанра** (`K_SORT_GENRE`) и **группы даты** (`K_SORT_DATE`) — у каждого
  свой. Сохранённое значение при старте валидируется по белому списку `BookDao.SORTABLE`
  (`isValidSort`), значения вне списка игнорируются. **Результаты поиска** режиму **не** подчиняются —
  всегда по названию (`SearchDao`).
- Имя автора показывается по настройке `S4.5`: **«Имя Фамилия»** (по умолчанию) или «Фамилия Имя».
- **Пагинация — только страницы**, для **всех** списков (подробности `UI.md §5.1`). Режим «показать
  ещё» отклонён: он не даёт самодостаточной страницы и хуже для «плохого зрения».
- **Одна страница → полосы страниц нет** (решение оператора): если листать нечего, полоса вместе
  с диапазоном `N–M из K` скрыта целиком — остаётся только область списка. Правило общее для
  `MainActivity` (вкладки/поиск) и `GroupBooksActivity` (`updatePager`).
- **Размер страницы — не константа**: `per_page(context)` = сколько строк помещается в область
  списка при текущем шрифте (`S4.3`), плотности (`S4.4`) и высоте экрана. Высота меряется по
  **фактической разметке вкладки**: строки классификаторов (`row_group`, ~107 px) и книг
  (`row_book`, ~230 px из-за обложки) разной высоты — считать их одной меркой нельзя.
- **Учёт групп (состав строк)**: страница — это набор строк **разных типов** (заголовок раздела +
  элементы), а не «высота / одна высота». Размер страницы считается по составу: набираем строки,
  пока суммарная высота (с учётом повторного заголовка разрезанной группы) не превысит область.
  Нумерация страниц зависит от этих настроек (подсказка `D12` это отражает).
- **Разрезанная группа не теряется**: если страница начинается посреди группы (буква/дата),
  заголовок раздела **повторяется** вверху страницы (макет `21`).
- Выборки — `LIMIT/OFFSET` по индексу сортировки; в курсоре всегда ≤ `per_page` строк (важно при
  1.6 ГБ ОЗУ). Для глубоких страниц (100k) — keyset по `(sort_key, id)` как ускорение к `OFFSET`.
- **Пересборка страницы после разметки, а не внутри неё**: размер области списка узнаётся из
  `onLayoutChange`, и там же пересчитывается `per_page`. Вызывать `setAdapter` прямо из этого
  колбэка нельзя — `AbsListView` в состоянии layout гасит `requestLayout`, и список остаётся пустым.
  Пересборка планируется через `View.post()` (см. `MainActivity`, `GroupBooksActivity`).
- **Алфавитный указатель** — **кнопка `ic_list` в строке поиска** (S1.1 «Авторы», S1.6 «Все книги» по
  названию). Полоса разделов у края списка **отклонена**: разделов по буквам 30–37, при крупном
  шрифте полоса становится нечитаемой на e-ink, поэтому указатель — кнопка, открывающая сетку `D13`.
  Сетка строится **динамически**: числа `0–9`, латиница `A–Z`, кириллица `А–Я` — только
  присутствующие разделы доступны (остальные приглушены), порядок «числа → латиница → кириллица».
  Тап по букве — вычисление страницы первой записи раздела и переход.
- `D12` «Перейти к странице» — нужен и при динамическом размере страницы (номеров ~2 000 при 100k).

### 6.7 Листание страниц (свайп и аппаратные кнопки, e-ink)

- Оси свайпа разделены (решение оператора, BACKLOG №2 и №12):
  - **вертикальный — листает страницы**: вверх — вперёд, вниз — назад; на границе —
    без эффекта (+ тост «первая/последняя страница»);
  - **горизонтальный в S1 — переключает вкладки** нижнего бара: справа налево —
    следующая, слева направо — предыдущая, циклически (от последней к первой и
    обратно); поведение полностью как у тапа по вкладке (сброс поиска, страницы,
    память активной вкладки в `Prefs`);
  - на экранах без вкладок (S2 «Книги группы») горизонтальный жест остаётся
    листовым — это поведение `SwipePager.Target` по умолчанию.
- Распознавание — на `ListView` (`ui/SwipePager`, `GestureDetector.onFling`):
  доминирующая ось при `|сдвиг| ≥ 48px` и больше второй модульной величины;
  диагональ уходит в горизонталь. События не перехватываются — тап и долгое нажатие работают.
- E-ink: смена страницы — без анимации, одно обновление экрана (NFR-2); тап по стрелкам полосы
  делает то же самое.
- **Аппаратные кнопки листают так же, как свайп**: верхняя — назад, нижняя — вперёд. Работают
  в `MainActivity` (S1) и `GroupBooksActivity` (S2) — все постраничные списки. Реализация —
  `ui/HwKeys` (`pageDelta`), переопределён `dispatchKeyEvent`.
- **Определение кнопок на RAPHAEL2** (замер `getevent`, 2026-11-01): кнопок на корпусе две — это
  **качель громкости** на устройстве `gpio-keys` (`/dev/input/event5`), ядро отдаёт `KEY_VOLUMEUP`
  (назад) / `KEY_VOLUMEDOWN` (вперёд). Но прошивка Onyx трактует их как **«боковые клавиши»**
  (глобальные настройки `key_custom_side_key_short_press_up=pageVolUp`,
  `..._down=pageVolDown`) и **присылает приложению уже `KEYCODE_PAGE_UP` (92) / `KEYCODE_PAGE_DOWN`
  (93)**, а не `VOLUME_*` — поэтому читалки, слушающие громкость (FBReader), их «не видят».
  `HwKeys` понимает **оба** семейства: `PAGE_*` (текущая настройка) и `VOLUME_*` (если в
  настройках Onyx переключат боковую клавишу обратно на громкость — или на другом устройстве).
  Проверка на живой кнопке: в лог приходил код `92`; инъекция `24`/`25` листала страницы.

## 7. Конвейер индексации

### Фаза A — обход + `stat` (приёмочный №9) — реализовано (M2)
1. Рекурсивный обход включённых корней; пропуск служебных каталогов (`Android`, `LOST.DIR`,
   `$RECYCLE.BIN`, `System Volume Information`) и всего скрытого (имя с `.`), `MAX_DEPTH = 64`.
2. Формат файла — по расширению (`BookFormat.detect`); «голый» `.zip` считается FB2-архивом
   (вся коллекция оператора — `.zip`); уточнение magic-байтами — Фаза B. Для книги снимаются
   `length()`+`lastModified()`; файл **не читается**.
3. Сверка с БД (`BookDao.touchSeen`): нет строки → `INSERT` (title = имя файла,
   `needs_parse=1`, `seen_gen = current`); есть и `size`/`mtime` совпали → **ни одной записи**;
   изменились → обновление служебных колонок + `needs_parse=1`. Служебные колонки не входят в
   `AFTER UPDATE OF` FTS-триггера, поэтому FTS не перестраивается зря.
4. **Доступность — проходом B по существованию, а не по `seen_gen`**: после обхода корня
   читаются его строки и у каждой проверяется `File.isFile()`. Пропал → `availability='missing'`
   (метаданные и связи сохраняются), вернулся → `'ok'`. Так повторный скан по неизменённой
   коллекции не пишет ни одной строки на файл (метка `seen_gen` сама по себе писала бы).
5. `dir_cache` **не реализован**: замер M9 на 100k — полный обход + сверка
   доступности 137 с, **0 записей в БД** (только `stat`). Для коллекции оператора
   этого достаточно; кэш каталогов — резерв оптимизации, если 100k станут
   открываться заметно дольше.
6. Транзакция — **на корень**: обрыв не оставляет «полу-скана», повтор безопасен (это только `stat`).
7. Прогресс публикуется не чаще ~200 мс / 128 файлов (`ProgressBus` → `IndexerService` +
   главный экран). Диагностика: `Indexer` логирует число записей в БД за обход
   (`SELECT total_changes()`) — это и есть машинная проверка «повторный скан — только `stat`».

### Фаза B — метаданные — реализовано для FB2 (M3a), EPUB (M3b), MOBI (M3c)
1. Отбор — **самовосстанавливающийся**: `(needs_parse=1 OR meta_ok=0) AND availability='ok'
   AND format IN (fb2, fb2zip, epub, mobi)`. Так разбираются новые/изменённые книги, а ранее не
   разобранные (`meta_ok=0`) перечитываются после исправления читателя. Это **все**
   поддерживаемые форматы — читатель есть у каждого.
2. **Keyset-пагинация по `id`** (батч 50): даже если транзакция батча провалится и `needs_parse`
   останется 1, проход продвигается вперёд — бесконечного цикла нет (учитывается в `skipped`).
3. На книгу — `MetadataReader` по формату (`fmt.fb2.Fb2Reader`, `fmt.epub.EpubReader`,
   `fmt.mobi.MobiReader`); потоково, без материализации `<binary>`/обложки. Кодировка —
   `EncodingSniffer`: **BOM снимается** (иначе XML-парсер падает на `U+FEFF` перед прологом).
   Zip с cp866-именами открывается общим хелпером `fmt.Zips.open` (UTF-8 → Cp866).
4. Запись — **транзакция на батч** (`MetaDao.writeMeta`): `book` + связи + FTS (перестраивается
   `book_au`) + материализованные счётчики. Битый файл → `meta_ok=0`, `needs_parse=0`, связи и
   денормализованные тексты очищены, title = имя файла, лог; индексация продолжается.
5. Прогресс — фаза `PHASE_PARSE` («разобрано N из M»).

### Фаза C — обложки (лениво)
`CoverStore` по `coverSpec` конкретного формата → декод → миниатюра ≤ 320 px (`RGB_565`) → файл;
`ThumbCache` — LRU по суммарному размеру.

## 8. UI под e-ink и «плохое зрение» (NFR-1, NFR-2)

> Полный инвентарь экранов, разделов, диалогов и типов строк — в **[`UI.md`](UI.md)**.

- **Глобальный масштаб шрифта** через override `Configuration.fontScale` (все `sp` масштабируются
  автоматически). Ползунок: 1.0/1.25/1.5/1.75/2.0.
- **Никаких фиксированных высот текста**: элемент списка `wrap_content`, у `TextView` **не
  ставить `maxLines`/`ellipsize`** (это и есть баг oreader). Длинные названия переносятся.
- **Автотест обрезки**: `uiautomator dump` сверяет bounding box текста с высотой элемента на
  fontScale 1.0/1.5/2.0 и на длинных названиях (приёмочный №7).
- E-ink: анимации выключены, высокий контраст, тач-цели ≥ 48dp, долгие операции — текстовый
  прогресс (без бесконечных «крутилок»).
- Главный экран — **строка поиска + 6 вкладок** (Авторы/Жанры/Серии/Дата/История/Все книги;
  вкладки — одна строка с прокруткой, у края со скрытыми вкладками стрелка `‹`/`›` — `UI.md §1`).
- **Группировка по буквам**: Авторы — по первой букве фамилии, Все книги (по названию) — по первой
  букве названия; разделы — числа/латиница/кириллица; заголовки разделов — обычные строки, не sticky
  (§6.6). Алфавитный указатель — кнопка `ic_list` в строке поиска, открывает сетку `D13`.
- **Пагинация** — везде страницы: полоса-пейджер + свайп (справа налево — вперёд) + `D12`;
  разрезанная группа повторяет заголовок на новой странице (§6.6, §6.7).
- **Иконки** — штриховые `drawable/ic_*` (tint `@color/icon`), а не текст, где это чище.
- **Локализация** — `values/` (ru, default) и `values-en/` (en), оба из `design/gen.py`.
- Карточка книги: обложка, все авторы/жанры/серии с номерами, аннотация, путь, формат,
  «Открыть», «Открыть в…», **«Удалить файл»** (`D11`), индикатор недоступности.

## 9. Запуск книги во внешней читалке (FR-5)

Полная матрица, разбор манифестов и кода — в **[`research/reader-launch-matrix.md`](research/reader-launch-matrix.md)**.
Фактически установлены и подтверждены **4 читалки** (`ru.plus.bookmate` из старого
`device/packages.txt` **не установлен**; AlReaderX на устройстве нет — только каталог-остаток):

| Читалка | Способ | Уверенность |
|---|---|---|
| `com.onyx.oreaderx` (OReaderX) | `content://` + MIME → компонент `com.neverland.viscomp.TMainActivity` | высокая |
| `com.fbreader` (FBReader) | `content://` + **обязательный MIME** → `...android.fbreader.FBReader` | высокая |
| `com.foobnix.pro.pdf.reader` (Librera FD) | `content://` + MIME → `com.foobnix.OpenerActivity` | высокая |
| `com.onyx.kreader` (NeoReader) | **`file://`** (при `content://` восстанавливает путь, поток не копирует) | высокая для `file://` |

Базовый интент:

```java
Intent i = new Intent(Intent.ACTION_VIEW);
i.setDataAndType(uri, mime);                       // ОБЯЗАТЕЛЬНО data+type вместе
i.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION);
i.setPackage(targetPkg);                           // адресный выбор читалки
startActivity(i);
```

- **MIME обязателен** (FBReader без него `content://` не матчит). Для мультиформата — по формату:
  fb2.zip → `application/fb2+zip` (совпадает у всех четырёх) либо `application/zip`;
  epub → `application/epub+zip`; mobi → `application/x-mobipocket-ebook`.
- **Базовый путь** — `content://` через обычный `FileProvider` (не MediaStore: foobnix
  опирается на `_display_name`/`_size`).
- **Fallback для `com.onyx.kreader`** — `file://` (все 4 имеют `MANAGE_EXTERNAL_STORAGE: allow`),
  либо FileProvider-алиас `external`. **Проверено на M7 (2026-11-01)**: `com.onyx.kreader` открывает книгу только через `file://` (с `content://` — ошибка), остальные три — через `content://`.
- Универсально-надёжный «последний» вариант для всех: `file://` + `application/fb2+zip`.
- `ReaderRegistry` — `PackageManager` + allowlist (`com.onyx.kreader`, `com.onyx.oreaderx`,
  `com.fbreader`, `com.foobnix.pro.pdf.reader`), метки и иконки; выбор default — в настройках,
  первый запуск — разовый диалог.
- Запись `last_opened_at`/`open_count`/`last_opened_by_package` после успешного `startActivity`.
- Нет читалки / запуск не удался — понятное сообщение (`D5`).
- Прогресс из чужих БД: у kreader (`Metadata.progress/lastAccess`), OReaderX
  (`recent.bookpos/datelast`), FBReader (`BookReadingProgress`) — извлекаемо; сопоставление
  **по пути/имени** (осторожно: `content://`-копии во временные каталоги могут ломать сопоставление).
- **Скрытие в лаунчере Onyx — не наш случай:** sideload-приложения показываются (14 из 26
  иконок — сторонние, включая наш Raphael Toolbox); `appsFilter` — серверный список.

## 11. Риски и меры

1. **ОЗУ 1.6 ГБ** → Java/no-Gradle (без AndroidX), `RGB_565`, лимиты кэшей, оконные курсоры. Профилировать на M1/M9.
2. **FTS5 нет** → FTS4+unicode61 (§6.1), тест на M0.
3. **Maven Central/Plugins Portal недоступны** → вариант A сети не требует (для Kotlin-варианта — прокси 9999); не блокирует.
4. **Читалка не принимает `content://`** → конкретика из research: `com.onyx.kreader` требует
   `file://` (либо FileProvider-алиас `external`), `com.fbreader` матчит только с MIME.
   **Митигировано** (§9): kreader получает `file://`, остальные — `content://`; проверено на M7.
5. **Лаунчер Onyx** → **снято**: sideload-апп видны (Raphael Toolbox, Magisk, FBReader, Librera FD);
   `appsFilter` — серверный, наших пакетов в нём нет.
6. **Съёмная SD** → `availability`, без автоудаления; «очистить отсутствующие» вручную.
7. **PDF/DJVU сняты с поддержки** (решение оператора): файлы не индексируются, строки удалены
   миграцией v3; обложек для них не требуется.
8. **Мультиформат раздувает объём работ** → этапы M3a–M3c отдельными шагами, каждый даёт
   самостоятельный результат; можно остановиться после любого.
9. **Оборвались на середине** → фазы идемпотентны, чекпойнты в БД.
10. **Безопасность** — на этом этапе `boot`/Magisk не трогаем; приложение ставится sideload’ом,
    удаляется штатно.
11. **Тесты на живой коллекции** → проверку «файл пропал/вернулся» (проход B) делать **только на
    временной копии внутри корня** (`cp` → переименовать копию), а не переименованием/удалением
    реальных книг: у устройства нет корзины, и потерянный файл вернуть неоткуда (см. отчёт по M2).
