# SPEC.md — InkShelf: каталог для e-ink читалки Raphael2

---

## 0. Резюме

Android-приложение-каталог и лаунчер локальной коллекции FB2 (`*.fb2.zip`). Индексирует файлы из нескольких корневых папок, строит навигацию по независимым классификаторам (авторы / жанры / серии / дата файла / история открытий / все книги), поддерживает быстрый полнотекстовый поиск и открывает выбранную книгу в одной из установленных читалок. Само чтение — не задача приложения.

**Масштаб:** проектировать на 100 000–500 000 файлов.
**Устройство:** e-ink, слабое железо, пользователь с плохим зрением (увеличенный шрифт обязателен и не должен ломать вёрстку).

**Что закрываем из существующих приложений:**
- oreader: клиппинг текста при увеличенном шрифте; отсутствие классификаторов кроме авторов; нет истории и сортировки по дате.
- onyx: нет классификаторов, только ручные полки (бесполезно при 1000+ книг).

---

## 1. Границы (scope)

### В scope
- Индексация FB2-книг из нескольких корней.
- 6 классификаторов + поиск.
- Карточка книги с метаданными и запуском во внешней читалке.
- Выбор читалки по умолчанию + «Открыть в…» для конкретной книги.
- Настройки корней, шрифта, читалки.

### Вне scope (не делать)
- Чтение и рендеринг FB2.
- Ручные полки, теги, рейтинги, заметки.
- Редактирование метаданных и переименование файлов.
- Дедупликация по содержимому.
- Форматы кроме FB2 (mobi/epub и т.п.).
- Сеть, аккаунты, синхронизация.
- Гарантированный приём прогресса чтения от читалок (опционально, если читалка отдаёт — сохранить).

---

## 2. Глоссарий

- **Корень** — одна из папок библиотеки (карта памяти, Downloads и т.п.), задаётся пользователем; может быть несколько.
- **Книга** — файл `*.fb2.zip` (или опц. `*.fb2`), однозначно определяется путём.
- **Индекс** — SQLite-БД с метаданными всех найденных книг.
- **Классификатор** — экран-список, группирующий книги по признаку.
- **Недоступная книга** — запись, чей файл отсутствует или чей корень без доступа, но метаданные сохранены.

---

## 3. Допущения

1. **Платформа:** Android. `minSdk` / `targetSdk` — уточнить; предлагается `minSdk 23`, `targetSdk` — актуальный.
2. **Доступ к ФС:** гибридно. Прямые пути (`java.io.File`) там, где доступно; **SAF (persistable URI)** как fallback для защищённых разделов (`Android/data`, внешняя карта на новых версиях). SAF-обход медленный — учитывать в стратегии сканирования (см. NFR-3).
3. **Читалки:** несколько на устройстве. Список формируется через `PackageManager` по Intent `ACTION_VIEW` (mime: `application/fb2+zip`, `application/zip`, `application/octet-stream`) + известный список пакетов. Передача файла — Intent с `file://` / `content://` (FileProvider). Механика выбора — автоподбор по возможности читалки, с ручным override.
4. **История:** «открыто из этого приложения» — фиксируем timestamp + пакет читалки. Получение прогресса — опционально.
5. **Корневые папки:** множество, каждая со своим статусом.
6. **Язык интерфейса:** русский.

## 4. Функциональные требования

### FR-1. Индексация

#### FR-1.1 Обход и парсинг
- Рекурсивный обход всех активных корней. Поиск `*.fb2.zip` (регистронезависимо), опционально `*.fb2`.
- Внутри zip: искать entry с расширением `.fb2`; иначе — самый крупный XML-подобный файл. Матчинг **по расширению**, не по точному имени (кривые/битые/cp866-имена).
- Кодировка fb2 — из XML-декларации (utf-8 / windows-1251 / др.).
- Извлекать:
  - название;
  - **все** авторы (с сохранением порядка);
  - **все** серии с номером в каждой (`<sequence name number>`, multiple, номер может отсутствовать);
  - **все** жанры (FB2-коды → человекочитаемые названия; маппинг — локальная таблица в коде);
  - обложка (`<coverpage><image l:href>` → `<binaries>`);
  - аннотация.
- Парсинг — потоковый (SAX/StAX-подобный), без загрузки XML целиком в память и без материализации `<binaries>`.
- Битый / нечитаемый файл: **пропустить с логом**, книга попадает в «Без метаданных» (название = имя файла). Индексация не прерывается.

#### FR-1.2 Инкрементальность (критично)
- Хранить в БД `path`, `file_size`, `file_mtime`. При повторном сканировании — только `stat`; если всё совпало — не перечитывать fb2.
- Пересобирать только новые/изменённые записи; удалённые — помечать недоступными (не удалять автоматически).
- Оптимизация: если возможно, отсекать неизменённые поддеревья по mtime каталогов.
- Сканирование — **фоновая служба** (`WorkManager` / foreground service) с чекпойнтами, переживает убийство процесса и продолжается с места остановки.
- Батч-транзакции (N записей за транзакцию), не по одной на книгу.
- Фазы: (a) обход+stat → (b) парсинг новых/изменённых → (c) обложки — лениво (FR-3).
- UI показывает текстовый прогресс (`просканировано / найдено / добавлено`), не блокируется. Уже проиндексированные данные доступны во время сканирования.

#### FR-1.3 Несколько корней и нестабильные тома
- Каждый корень — запись со статусом: URI/путь, тип доступа (`file` / `SAF`), включён, `last_scan_at`, `volume_state`, `permission_state`.
- Том не смонтирован / разрешение отозвано → книги корня помечаются **«Недоступные»**, метаданные сохраняются. При восстановлении доступа → снова доступны **без полной переиндексации** (проверка по mtime).
- Действие «Очистить отсутствующие» (вручную, в настройках).
- Дубликат файла по разным путям — отдельные записи (дедупликация по содержимому вне scope).

### FR-2. Классификаторы

Главный экран — переключаемые вкладки/боковое меню. Обязательные:

1. **Авторы** — список авторов + счётчик книг; tap → книги автора. Книга с несколькими авторами присутствует у каждого.
2. **Жанры** — список жанров + счётчик; tap → книги жанра. Книга с несколькими жанрами присутствует в каждом.
3. **Серии** — список серий + счётчик; внутри сортировка по номеру книги в серии, книги без номера — в конце. Книга с несколькими сериями присутствует в каждой; в карточке книги отображаются все серии с номерами.
4. **Дата изменения файла** — группировка: Сегодня / Вчера / На этой неделе / В этом месяце / Раньше; внутри — по `file_mtime` убыв.
5. **История открытий** — «Недавно открытые» (по `last_opened_at` убыв.), «Открытые» (все когда-либо), опционально «Не открывавшиеся».
6. **Все книги** — плоский список, сортировки: название / автор / дата файла / дата индексации.

Общее:
- Счётчики у каждой группы/классификатора.
- Поиск доступен с любого списка.
- Быстрый переход к карточке книги.

### FR-3. Отображение книг и обложек
- Элемент списка: обложка-миниатюра + название + авторы (+ серии/номера).
- **Обложки не извлекаются пачкой при индексации.** Стратегия:
  - ленивое извлечение при показе элемента;
  - упреждающая подгрузка для окна прокрутки;
  - диск-кэш миниатюр LRU с ограничением размера (например, 64 МБ, настраивается);
  - плейсхолдер, если обложки нет.
- Списки — виртуализация/пагинация; в памяти только видимое окно.
- Карточка книги: обложка, полные метаданные (все авторы / жанры / серии с номерами), аннотация, путь, кнопки «Открыть» и «Открыть в…», индикатор недоступности если файла нет.

### FR-4. Поиск
- По названию, авторам, серии. Подстрока без учёта регистра.
- **FTS5** (SQLite) с external content + триггерами, токенизатор `unicode61`, префиксный поиск.
- Целевая задержка ≤ 300 мс на 100k+.
- Результаты — плоский список с пагинацией; подсветка совпадений по возможности.

### FR-5. Запуск книги и выбор читалки
- Список установленных читалок — через `PackageManager`; в настройках — выбор по умолчанию.
- Tap по книге → открыть в читалке по умолчанию. Долгое нажатие / пункт «Открыть в…» в карточке → список установленных читалок для этой книги.
- Передача файла: `Intent.ACTION_VIEW` с `content://` (через FileProvider); если читалка не умеет — fallback на `file://` (если путь доступен). Автоподбор с ручным override.
- Читалка не найдена / запуск не удался — понятное сообщение.
- Фиксировать в БД: `last_opened_at`, `open_count`, `last_opened_by_package`.

### FR-6. Настройки
- **Корневые папки:** добавить (SAF-пикер или прямой путь), удалить, включить/выключить. Для каждой — статус доступа и `last_scan_at`.
- Читалка по умолчанию.
- Размер шрифта интерфейса (глобально).
- Кнопка «Пересканировать библиотеку» (полный рескан).
- Действие «Очистить отсутствующие».

## 5. Нефункциональные требования

### NFR-1. Динамическая вёрстка (критично, баг oreader)
- **Ни одна строка текста не должна обрезаться ни при каком размере шрифта**, включая максимальный.
- Высота элемента списка — по фактическим метрикам шрифта (измерение, wrap, `wrap_content`), без фиксированных dp для текста.
- Многострочные названия переносятся, элемент растёт по высоте.
- Отдельный приёмочный тест (§9.7).

### NFR-2. E-ink
- Без анимаций, плавного скролла, overscroll-эффектов; минимум полных перерисовок.
- Высокий контраст, крупные тач-цели.
- Долгие операции — текстовый прогресс, без бесконечных «крутилок».

### NFR-3. Производительность при 100k+
- **Индексация:** первичный проход — длительная операция (часы на слабом железе); фоновая служба, чекпойнты, поэтапный прогресс, доступность уже готовых данных. Инкрементальный рескан неизменённой библиотеки — только `stat` по файлам, fb2 не перечитываются.
- **Парсинг:** потоковый, без материализации `<binaries>`.
- **UI:** холодный старт при готовом индексе ≤ 3 с. Прокрутка — плавная (виртуализация/пагинация).
- **Счётчики классификаторов:** материализовать/кэшировать (агрегатные таблицы или инкрементальное обновление), не считать «в лоб» на каждый показ.
- **Поиск:** FTS5, ≤ 300 мс.
- **Индексы БД:** на все часто сортируемые/фильтруемые поля.
- **Обложки:** ленивое извлечение + дисковый LRU-кэш миниатюр; полные изображения в память не грузятся.

### NFR-4. Надёжность
- Битый fb2/zip не валит индексацию.
- Индекс переживает перезапуск; сканирование продолжается с чекпойнта.
- Изменение/удаление корней → корректная переиндексация/пометка недоступных.
- Отзыв SAF-разрешения обрабатывается без падения.

### NFR-5. Прочее
- Полностью офлайн, без сетевых разрешений.
- Никакого ручного груминга полок/тегов.

## 6. Модель данных (минимум)

### Схема
```
root(id, uri, kind[file|saf], enabled, last_scan_at, volume_state, permission_state)

book(
  id, root_id, path, file_size, file_mtime,
  title, annotation,
  cover_state[none|pending|cached], cover_cache_path,
  indexed_at, availability[ok|missing|no_access],
  last_opened_at, open_count, last_opened_by_package
)

author(id, full_name)
book_author(book_id, author_id, ord)              -- PK(book_id, author_id)

genre(id, code, display_name)
book_genre(book_id, genre_id)                     -- PK(book_id, genre_id)

series(id, name)
book_series(book_id, series_id, number NULL)      -- PK(book_id, series_id)

-- FTS5 (external content):
book_fts(title, authors_text, series_text) CONTENT='book', content_rowid='id'
-- триггеры на insert/update/delete book
```

### Индексы
- `book(path)` UNIQUE, `book(file_mtime)`, `book(last_opened_at)`, `book(title)`, `book(root_id)`.
- Все FK-таблицы.
- Для классификаторов — агрегатные счётчики (`author_book_count`, `genre_book_count`, `series_book_count`) или инкрементальное обновление при вставке/удалении.

## 7. Технологический стек (предлагаемый)

- **Язык:** Kotlin.
- **БД:** Room + SQLite FTS5 (external content). Миграции — обязательно.
- **Сканирование:** WorkManager (устойчивый к перезапуску) + foreground service для прогресса.
- **Списки:** Paging 3 + виртуализированный RecyclerView; без анимаций.
- **Обложки:** Coil (или ручной LRU + Glide-подобный кэш); дисковый кэш ограничен.
- **Запуск книг:** `PackageManager` + `FileProvider`.
- **SAF:** `DocumentFile` / `DocumentsContract` (по возможности — прямые пути для скорости).
- **DI:** Hilt (или ручной).
- **Логи:** Timber.

## 8. Разбивка на задачи (для агента)

1. **Основа:** проект, DI, БД (Room), миграции, схема из §6, FTS5.
2. **Сканер:** обход корней (file + SAF), stat-инкремент, чекпойнты, парсер FB2 (потоковый, кодировки, множественные авторы/жанры/серии), обложки — только пути в БД.
3. **Классификаторы + счётчики:** 6 экранов, агрегаты, сортировки, группировка по mtime.
4. **Поиск:** FTS5, триггеры, экран результатов.
5. **UI-списки:** виртуализация, динамическая вёрстка (NFR-1), карточка книги.
6. **Обложки:** ленивое извлечение, LRU-кэш, плейсхолдер.
7. **Запуск книг:** список читалок, default, «Открыть в…», фиксация в БД.
8. **Настройки:** корни (CRUD, SAF), шрифт, читалка по умолчанию, рескан, очистка недоступных.

Порядок имеет смысл. Ветка задачи 5 может идти параллельно 2–4 при готовой схеме.

## 9. Приёмочные критерии

1. На коллекции **100 000+** `*.fb2.zip` в нескольких корнях индекс строится устойчиво (переживает перезапуск), книги видны во всех классификаторах.
2. Счётчики автора/жанра/серии равны числу книг в соответствующем списке; книга с несколькими авторами/жанрами/сериями присутствует во всех группах.
3. В карточке книги отображаются **все** её авторы, жанры и серии с номерами.
4. Серии отсортированы по номеру; без номера — в конце.
5. Группировка по mtime корректна.
6. После открытия книга вверху «Недавно открытые»; зафиксирован пакет читалки.
7. **При максимальном шрифте названия книг видны полностью, без обрезки.**
8. Обложки есть там, где есть; иначе плейсхолдер; кэш ограничен.
9. Инкрементальный рескан неизменённой библиотеки не перечитывает fb2 (только stat) и укладывается в приемлемое время на 100k.
10. Битый zip/fb2 не ломает индексацию.
11. При нескольких читалках можно задать default и открыть конкретную книгу в другой.
12. При отключённой SD-карте книги → недоступны; при возврате — доступны без полной переиндексации.
13. Холодный старт при готовом индексе ≤ 3 с; поиск ≤ 300 мс; прокрутка плавная.

---

## 10. Явные «не делать» (напоминание агенту)

- Не реализовывать ридер.
- Не делать ручные полки/теги.
- Не тянуть в память `<binaries>` целиком и не извлекать обложки пачкой на индексации.
- Не грузить весь список в память; всё через пагинацию.
- Не задавать высоту строки списка в dp — только по метрикам шрифта.
- Не добавлять сеть/аккаунты.
